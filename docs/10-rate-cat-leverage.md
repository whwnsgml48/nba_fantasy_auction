# 10 · 비율 캣 볼륨 레버리지 — 로스터 실측 기반

3PT%에만 있던 볼륨 레버리지 계산을 **FG%·FT%로 확장**하고, 고정 가정이던 팀 시도량을
**그 코어 로스터의 실제 합**으로 바꿉니다.

재현: `python3 tool/rate_cat_leverage.py` (파일을 쓰지 않고 표준출력만 냅니다)

## 무엇이 낡았나

| 위치 | 낡은 서술 | 실제 |
|---|---|---|
| `README` 「평가자에게」 4번 | "FG%·FT%는 **시도량 데이터가 없어** 같은 계산을 못 했습니다" | **14차에 낡음** — `measured_full.json`에 `FGA`·`FTA`가 171명 전원 있다 |
| `docs/05` 5번 | "팀 3PA 135는 실측이 아님" | 유효한 지적 — 아래에서 실측으로 대체 |
| `docs/05` 5번 | "레버리지는 로스터 구성에 따라 달라져야 하는데 고정값을 씀" | 유효한 지적 — 아래에서 코어별로 분리 |

`docs/03` 34행은 이미 *"시도량(FGA·FTA·3PA)이 있어 비율 캣도 레버리지 계산 가능"* 이라고
적어놓고 **3PT%만 계산했습니다.** 데이터가 아니라 계산이 빠져 있었습니다.

## 공식

```
지분     = 내 주간 시도 / 팀 주간 시도
레버리지 = 지분 × (내 rate − 기준선) × 100     [pp]
변동성   = √(p(1−p)/주간시도) × 100            [이항 SD]

주간 시도 = 경기당 시도 × 3.5경기 × 가용률(GP/82)   ← cat_model.avail()과 같은 가중
```

기준선은 `cat_model.baselines()`(지명 풀 126명 · **시도량 가중**)를 그대로 씁니다 —
3P% 36.4% · FG% 48.7% · FT% 79.8%. 정의는 `docs/03`의 3PT% 표와 동일하고,
**바뀐 것은 분모가 고정값이 아니라 로스터 합이라는 점 하나**입니다.

실제 3PA 합 평균(**89.9**)을 계산하고, 산문의 `주 3.5경기 · 팀 3PA 135` 가정도 갱신했습니다.

- 분모가 실제보다 **26 ~ 85% 컸습니다**(135 vs 73~107) → 옛 `docs/03` 3PT% 표의 19명이 전원 과소 계상
- 같은 선수의 3PT% 레버리지가 코어에 따라 **최대 1.46배** 달라집니다

`docs/05` 5번이 *"빅맨 헤비 로스터는 팀 3PA가 훨씬 낮아지므로 같은 선수의 지분이 커진다"*

## 2. FG%·FT% 계산 결과 — 코어별 팀 합

| 코어 | 3P% 합 | FG% 합 | FT% 합 |
|---|---|---|---|
| c1 | +0.71 | +1.96 | −5.93 |
| c2 | −0.35 | +1.03 | **−2.66** |
| c3 | −1.49 | +4.09 | −3.19 |
| c4 | −1.87 | +3.45 | −5.96 |
| c5 | +0.01 | **+4.94** | **−7.04** |
| c6 | **−3.08** | +1.30 | −4.16 |
| c7 | −0.05 | +2.08 | −6.06 |

읽는 법 세 가지.

1. **FG%는 7코어 전부 플러스**(+1.03 ~ +4.94), **FT%는 7코어 전부 마이너스**(−2.66 ~ −7.04).
   `docs/01`의 핵심 주장("빅맨 중심 로스터는 FG%를 얻고 FT%를 내준다")이 **수치로 확인**됩니다.
2. **3P%는 코어마다 부호가 갈립니다** — c1 +0.71 / c6 **−3.08**. 정상 시장 기본값인 c6가
   3PT%에서 가장 나쁩니다. c6의 3P% 최고 기여자가 **Towns +0.35**뿐입니다.
3. FG% 최대는 c5(+4.94), FT% 최악도 c5(−7.04) — **같은 코어**입니다. 빅맨을 더 쌓으면
   한쪽이 오르고 다른 쪽이 내려가는 것이 한 로스터 안에서 보입니다.

## 4. 교차검증 — 승률 모델과 순위가 맞는가

이 레버리지 모델(결정론적)과 `matchup_sim`(몬테카를로)은 **완전히 다른 계산**입니다.
FT% 기준으로 두 모델의 코어 순위를 대조했습니다.

| 코어 | FT% 합 (pp) | FT% 최저 승률 |
|---|---|---|
| c2 | −2.66 | 0.238 |
| c3 | −3.19 | 0.203 |
| c6 | −4.16 | 0.163 |
| c1 | −5.93 | 0.113 |
| c4 | −5.96 | 0.096 |
| c7 | −6.06 | 0.101 |
| c5 | −7.04 | 0.090 |

```
레버리지 순위: c2 c3 c6 c1 c4 c7 c5
승률 순위    : c2 c3 c6 c1 c7 c4 c5
```

**7개 중 5개 위치가 일치**하고, 어긋난 c4↔c7은 레버리지 차이가 **0.10pp**(사실상 동률)입니다.
독립적인 두 모델이 같은 결론을 냅니다 — 두 모델 다 정상 작동한다는 근거입니다.

## 남은 한계

1. **주간 경기수의 분산은 미반영입니다.** 평균은 38차에 3.299로 실측화했지만(확정 일정
   174일 = 24.857주 · 82경기), 이 모델은 평균을 쓰고 `matchup_sim`은 `{3,4}` 지지집합에
   4의 확률 0.299를 실어 뽑습니다(SD 0.458). 관측된 한 주(30팀)의 실제 SD는 **0.745**로
   더 넓습니다 — 근거가 n=1주여서 미적용이고, 후보 분포는 `cat_model` 주석에 남겼습니다.
2. **변동성(이항 SD)을 표에 넣지 않았습니다.** `docs/03`의 3PT% 표는 변동성을 함께 보여
   "rate 1위 Kennard의 레버리지는 8위, 변동성은 1위" 같은 판단을 가능하게 했습니다.
   FG%·FT%에도 같은 열이 필요합니다 — 스크립트에 `vol()` 함수는 있고 출력만 안 합니다.
3. 🔴 **`players.json`의 `volume_leverage` 필드는 여전히 갱신하지 않았습니다.** 19명이
   고정값 135로 계산된 문장을 그대로 갖고 있습니다. 갱신하려면 코어별로 값이 달라지므로
   **필드 하나에 담을 수 없습니다** — 스키마 변경(코어별 dict)이 필요하고 그건 사람 판단
   사항입니다. (`docs/03`의 표 자체는 38차에 생성기를 고쳐 해소했습니다.)
4. 이 문서의 숫자는 **작성 시점 로스터** 기준입니다. 피벗 재설계가 진행 중이므로
   base가 바뀌면 스크립트를 다시 돌려야 합니다.
